ReconLoop

Razorpay settlement reconciliation, graded against an answer key

Settlements against the bank statement, payments against invoices, refunds against credit notes, plus a fee and GST audit. Rules do almost all of the work, and every synthetic batch ships with an answer key, so every run below is scored: what it linked, what it got wrong, and what it handed back to a person.

Rules only sends anything unclear to a person. Greedy baseline always takes the top candidate and never abstains: run it on the same seed and watch the wrong links appear. Oracle ceiling reads the answer key; it is the ceiling a perfect tie-breaker could reach, not a result. The Claude tie-breaker is not offered here, because calling it from a public page would mean shipping an API key to every visitor. It lives in the repo's server app.

Reconcile your own three CSVs. Your files never leave this tab: the Python engine runs here, in your browser, so nothing is uploaded anywhere. They need the same columns as the sample batch: Razorpay's settlement recon report (amounts in paise), a bank statement (rupees, DD-MM-YYYY) and your books (invoices and credit notes). With no answer key there is no accuracy score, but you still get the report, the exceptions, the review queue and the proposed actions.

Why it runs in your browser

The engine is plain Python with no dependencies, so this page loads it into your browser with Pyodide (CPython compiled to WebAssembly) and runs it there. No server does any work, which is why it is free to host and why your uploaded files stay on your machine.
